== Resumen del proyecto

* **Producto:** videojuego de batallas por turnos con aves de Chile.
* **Plataforma:** navegador web moderno y aplicación web progresiva (PWA) instalable.
* **Motor:** TIC-80 con programación en JavaScript.
* **Mecánica principal:** batallas 4 contra 4 que combinan la resolución de *Piedra, Papel, Tijera, Lagarto, Spock* (PPTLS) con estadísticas y movimientos tipo Pokémon.
* **Contenido base:** diez aves chilenas, cada una con imagen, sonido, descripción, cuatro movimientos activos y un movimiento distintivo.
* **Pantallas:** Inicio, Selección de equipo, Batalla, Ganador y Perdedor.
* **Entregables:** código fuente en GitHub, juego PWA público, manual de usuario web, tráiler en YouTube y documentación técnica en Antora.

== Cómo leer esta documentación

1. Comienza por el xref:prd:vision-objetivos.adoc[PRD: visión y objetivos] para entender el propósito del juego.
2. Revisa el xref:prd:reglas-batalla.adoc[sistema de batalla] y el xref:prd:contenido-aves.adoc[contenido de las aves], que son el corazón del producto.
3. Consulta los xref:prd:requisitos-funcionales.adoc[requisitos funcionales] y xref:prd:requisitos-no-funcionales.adoc[no funcionales] antes de implementar.
4. Usa la xref:uat:matriz-trazabilidad.adoc[matriz de trazabilidad] para verificar que cada requisito tenga cobertura de aceptación.
5. Ejecuta los xref:uat:casos-inicio-seleccion.adoc[casos UAT] y registra los resultados en el xref:uat:registro-resultados.adoc[registro de resultados].

== Convenciones

* **RF-###**: requisito funcional.
* **RNF-###**: requisito no funcional.
* **BR-###**: regla de negocio o de batalla.
* **UAT-XXX-###**: caso de prueba de aceptación.
* **A-###**: supuesto o decisión abierta.
* **Must / Should / Could**: prioridad MoSCoW.
